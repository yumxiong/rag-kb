## 固定实验设计

[验收脚本](../../scripts/acceptance/step5/paid_model_comparison.py) 默认只打印计划，
只有显式 `--execute` 才调用供应商。使用已跟踪的 AtlasDesk 9 份虚构公开文档，
逐文件核对 manifest SHA256；32 个分块、5 道既有问题。不得读取私人历史评测集。

两个模型使用同样的 1000 字符分块、200 重叠、1024 维、批量配置 10 和 15 秒超时。
保留最近 2 个片段，MMR 使用 k=6、fetch_k=24、lambda=0.3，去重后最多 6 个证据。
分别创建独立新索引，候选新模型先跑，再跑 v3；任一步失败即停，不自动重试。
每个模型一次短文本探针、32 条文档、5 个查询；查询在最近邻与 MMR 间复用缓存。
最后一次 DeepSeek 非思考连通探针，最大输出 800 token，45 秒超时。

计划合计最多预留 4.794048 元；单轮硬限 6 元/100 次发送尝试，且受共享每日
50 元账本限制。记录 token usage 原始整数与保守预留，不能把预留当成实际账单。
完整证据要求检索出的片段包含题集中指定的原文且来源文件正确；跨文档题必须
同时覆盖全部来源。4 道可回答题有该指标；无答案题只记录返回来源，不靠检索
排名声称拒答正确。本轮只有一条聊天连通探针，不是完整 RAG 答案质量验收。

这是一组已用于开发的演示题，不是独立盲测；结果相同仅证明该小样例未见退步，
不能证明新模型的普遍提升。两个模型顺序运行，耗时不能作为严格并发性能比较。

## 密钥、账本与证据

显式指定的密钥文件仅由验收程序读入内存，禁止输出密钥、原始异常文本、请求头
或供应商错误响应全文。清空配置环境、屏蔽 dotenv 与 keyring，不加载真实 `.env`。
只通过带金额保护的 HTTP transport 调用已审核的两个端点。

本地固定账本：`rag-step5-local-paid-state/ledger`；独立 reference：
`rag-step5-local-paid-state/reference/anonymous-store-reference.json`。
首次且仅首次使用 `--initialize-ledger`；后续运行必须复用，不能按运行日期新建账本。
该目录虽然匹配历史 Git ignore 模式，**包含真实付费预留，绝不是可清理的合成证据**。
禁止提交、删除、清零或用旧备份覆盖。迁移到服务器前须核对当天消费和未决项，
不能通过服务器重新初始化来获得另一份当天 50 元预算。

Windows 此处使用显式 development 存储模式，保留原子替换、文件 fsync、进程锁
及共享金额限制，但不宣称断电时目录元数据持久化；Linux 生产挂载/断电/恢复验收
另行进行。运行中断后保留账本及所有未决金额，不依靠当天重跑退款。

每轮必须给出一个尚不存在的 `rag-step5-local-*` 输出目录，保留独立索引、缓存及
脱敏 `summary.json`。不覆盖已有运行，不将索引或账本提交 Git。

## 下一步方向

建议首次部署保留 v3，暂不升级 qwen3.7。现有候选配置仍指向 qwen3.7 和其独立
索引，**不能直接用作最终上线配置**。决定保留 v3 后，应把候选模型与索引目录
一起调整为独立的 v3/1024 身份，新建匹配索引；不得复用无身份标签的旧索引。

下一阶段应在确认模型选择后，以同一金额账本完成有限的端到端回答/引用/拒答
回归，再显式重建最终知识库、固定新应用基线并构建/验收交付镜像。目标 Linux 的
持久化、恢复、容量及公网验收尚未完成。远端准备、证书签发、应用启动仍分别授权。

若以后继续研究新模型，应先核对其 query/document 输入约定和推荐检索方式，
另立实验、加入更广且未用于调参的题集，再比较召回与最终答案；本轮不自动调参。
