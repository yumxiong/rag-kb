# AtlasDesk 身份与访问

AtlasDesk 的访问管理围绕当前工作区展开。团队应根据成员承担的工作分配角色，并在人员职责变化时重新检查。一个成员在某个团队中负责维护内容，并不能据此推断其在另一个团队中也具有相同权限。开始管理操作前，先确认当前工作区和当前身份，可以减少把团队边界误认为操作故障的情况。

## 成员角色

下表用于区分日常协作职责。团队应按实际任务选择角色，不宜把较高权限作为默认安排。需要阅读材料的人员和需要维护材料的人员承担不同责任，角色选择应让这种区别清楚可见。

| 角色 | 日常职责与边界 |
|---|---|
| Owner | 负责工作区的最高管理职责 |
| Admin | 可以邀请成员并管理知识库，但不能更换工作区归属人 |
| Editor | 负责知识库内容的编辑与维护 |
| Viewer | 阅读和检索已获授权的内容 |

成员角色应与具体工作联系起来。例如，只需要查阅处理说明的同事不必承担内容维护职责，而负责整理流程的人需要理解自己修改的材料会影响哪些读者。团队可以把角色安排与内容负责人名单一起核对，避免因职责描述模糊而让成员长期使用不适合的权限。

## 组织登录

SAML SSO 仅对 Enterprise 开放；OIDC 登录在 Standard 和 Enterprise 都可使用。选择登录方式时，应先确认套餐和组织采用的身份体系，再进行相应配置。能完成组织登录不代表已经拥有某个工作区内的管理权限，成员进入团队空间后仍按其分配的角色开展操作。

配置人员应与负责身份体系的同事确认登录对象和使用范围。日常成员需要知道自己应使用哪一种组织身份，尤其是在参与多个团队时。排查进入团队空间后的操作问题，应把身份是否正确与角色是否满足要求分开核对；混在一起判断，容易把权限不足误认为登录失败，也容易在错误的方向上反复修改配置。

团队介绍登录安排时，可以同时说明当前空间的用途与成员职责。新成员往往只记得自己曾经完成登录，却不清楚正在访问的资料属于哪个团队。让成员确认空间名称和工作任务，有助于减少无关的权限申请。操作需要额外职责时，应由团队确认实际需求，再按现有分工处理。

## 自动化身份

服务账号在 Standard 和 Enterprise 都可使用，其 token 绑定一个工作区。需要让自动化程序访问不同团队空间时，应分别规划对应的身份配置，不能把同一个凭据当作通用的组织入口。程序的目标空间和凭据所属空间应在配置时保持一致，这也是排查访问问题时需要核对的基础信息。

自动化配置应有明确的维护人员。团队需要知道哪项任务使用了什么身份，以及在任务用途发生变化时由谁检查配置。用于程序的凭据不应混入面向普通读者的知识材料，也不应依靠聊天记录传递来承担长期配置管理。交接说明可以描述配置的位置和用途，但不需要包含凭据本身。

自动任务出错时，先核对其所要访问的团队空间是否与配置意图一致，再检查执行的操作是否符合身份安排。若程序原本只为一个团队整理材料，后来被用于其他任务，应重新评估配置范围。通过明确用途减少身份混用，比在多个脚本中反复复制同一份配置更便于排查。

## 日常权限检查

建议把权限检查放在真实工作流程中进行。维护人员可以列出一个成员需要完成的任务，再逐项确认其角色是否合适。不要只问对方能否打开页面，还要确认其是否需要修改内容、参与团队管理，或者只是阅读现有说明。这样讨论权限时会有明确依据，也容易解释为什么某些操作不属于当前职责。

当成员遇到操作受限时，可以先记录当前工作区、当前身份和预期完成的任务。负责处理的人据此检查角色安排，而不必先猜测系统是否发生故障。操作入口的出现与否不能代替对职责的理解，团队仍应以已确认的权限规则为依据。需要扩大职责时，也应由负责管理的人员确认工作需求。

人员调动后，应重新核对原来的安排是否仍然适用。曾经负责整理材料的成员可能转为阅读者，新接手的维护人员则需要理解内容边界。交接时把未完成的维护任务、涉及的主题和角色安排一起说明，比只交付一份文件列表更容易保证后续工作继续进行。

对于临时协作，也应在开始时说明工作范围和结束时如何复核。临时需要帮助整理某个主题，不意味着对方长期承担整个团队的管理职责。清楚记录任务目的，可以帮助管理人员在协作结束后判断是否还需要原来的安排，也能减少成员对自己应处理哪些事情的误解。

## 管理职责交接

只有 Owner 可以执行工作区所有权转移，Admin、Editor 和 Viewer 均不能执行该操作。需要交接最高管理职责时，应由现任归属人处理；日常管理权限不能替代这项权限。交接涉及的是工作区的负责关系，应与普通内容维护人员的更替区分开来。

准备交接时，建议相关人员先确认目标团队空间和接手对象，避免仅凭相似名称判断。接手人员也应了解当前知识库结构、成员职责和仍待处理的问题。确认职责变化后，再按团队安排进行后续维护，不能只把一次操作完成当作全部交接工作结束。

管理交接说明适合记录由谁负责后续协调、哪些内容正在整理以及有哪些需要继续确认的事项。无需在说明中复制自动化凭据，也不要把个人登录信息当作交接材料。让接手人员理解现有分工和待办事项，才能使新的负责关系在日常协作中发挥作用。
