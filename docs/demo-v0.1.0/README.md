2026-09-21 确定：使用 `atlasdesk-demo-v1` 的 9 份原文快照、4 个首页问题、1 个无答案边界题，以及 DeepSeek/Qwen 模型链路。应用正式 tag 尚未创建。

## 内容与来源

AtlasDesk 是本项目编写的虚构产品资料，不包含真实客户数据。维护者已选定其用于公开演示；此处不新增独立第三方授权声明。逐文件标题、来源路径、来源提交、字节数和 SHA-256 见 [manifest.json](manifest.json)。文档覆盖产品套餐、身份权限、文档接入、检索生成、API 任务、配额计费、安全保留、故障排查和版本说明。

来源分支 `feat/public-eval-corpus` 的评测工程尚未正式冻结。本目录只保存 9 份原文，不合并其代码、题集或评测产物。复制时源文档无未提交修改，快照保留工作区原始字节；manifest 同时记录 Git blob 的哈希，以区分检出时的换行转换。源分支后续变化不会自动进入本快照。

只导入 manifest 的 `ingestion_allowlist`，即 `corpus/` 内的 9 份 Markdown。不要导入本说明、manifest、问题集、模型配置或上线记录，也不要复制开发环境向量库、缓存及任务数据。后续首次入库在独立数据目录进行，等待全部处理完成后再验证。来源说明中的约 32 个分块仅供参考，当前部署版本的实际分块数需在第 7 步记录。

首页用途与范围文案（第 4 步接入）：

> 本演示使用为项目编写的 AtlasDesk 虚构产品文档，展示知识库检索、问答与来源追溯。资料中的套餐、配额和产品能力仅用于演示，不代表本站实际功能或服务承诺。访客无需登录即可提问和查看引用，知识库由管理员维护。

## 示例问题与验收

[questions.json](questions.json) 保存 4 个首页问题和 1 个仅用于验收的边界问题，包含预期事实、原文证据及禁止推断。按钮只提交问题，答案仍由真实检索和模型生成；本文件不作为运行时答案来源。开发集复用题的来源 ID 已记录，不能再将这些题作为独立测试集证明泛化能力。

第 4 步逐题验证匿名问答，第 7 步在干净 Docker 环境复验，第 10 步外网验收。每次记录提交、语料版本、模型、缓存状态、回答要点、实际引用、耗时和通过/失败。首次真实链路验证须使用空问答缓存，避免只验证缓存结果。

- 回答必须包含全部必要事实，允许措辞变化，不逐字匹配整篇答案。
- 引用必须展示来源文件及支持事实的原文；章节用于人工定位，不要求当前 UI 已支持章节元数据。Markdown 不强求页码，不绑定重建后可能变化的 chunk ID。
- 跨文档题必须同时覆盖两个来源，只有一个来源不通过；无关来源不能替代必要证据。
- 无答案题应明确资料未提供报价，不编造价格或把无关引用包装成报价依据。返回了检索片段不等于这些片段能回答问题。
- 首页 4 题应全部通过；失败时定位检索、上下文或生成问题，不用预置答案掩盖故障。

## 模型与索引约定

[models.env.example](models.env.example) 明确指定 `deepseek-flash` 和 `text-embedding-v3`，无需依赖提供商默认映射。该文件只是模型及检索参数片段，不是完整生产配置，也不会被应用自动加载。部署时将这些项合入独立生产配置，凭证通过服务器 secrets 单独提供。Qwen 使用中国区 DashScope 兼容端点，需在后续验证账号及服务器可用性。

2026-09-23 已完成本地真实 API 验收：9 份文档、32 个分块，Qwen 不额外传 dimensions，实际向量维度为 1024；DeepSeek 探针返回型号 `deepseek-flash`。5 道题均关闭问答缓存后通过，见 [验收结果](acceptance-2026-09-23.json)。分块 1000、重叠 200、来源上限 3、温度 0.1、输出上限 800 tokens；DeepSeek 使用非思考模式。全库检索保留最近的 2 个片段，再由 MMR 补足到 6 个去重片段，候选数 24、lambda=0.3。该参数只在本演示开发样例上验证，不代表通用检索指标提升。每访客与全站额度在第 5 步确定，输出上限不替代成本配额。

浏览器截图：[桌面](assets/step4-desktop.png)、[移动视口](assets/step4-mobile.png)。截图中的 40 次额度仅用于独立本地验收，不是生产额度；截图拍摄后输入提示已缩短，以避免窄屏多行截断。当前布局也不是完整 UI 联调的最终版本。Docker 和外网仍须在第 7、10 步复验。

更换语料、Embedding 模型/维度或分块参数时，另行安排索引重建和回归。聊天模型变化也需回归，并检查或失效旧问答缓存。不要覆盖正在服务的生产索引。快照后续修订应记录新语料版本和哈希，不随意改动已发布版本。
