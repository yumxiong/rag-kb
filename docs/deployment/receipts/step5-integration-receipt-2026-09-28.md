## 下一阶段：共享契约评审

deploy 可开始拟定 `docs/api/anonymous-session-and-quota.md`，integration 负责审阅浏览器调用可行性并返回意见。此前清单里的端点、Cookie/Header、状态码和字段均为候选示例，不是已经冻结的 API。

评审必须明确以下事项：

1. 浏览器与 Streamlit 两条链路的身份初始化、验证、传递、过期、刷新及重连行为；是否要求同一浏览器跨两套前端共享身份。后端返回给 Streamlit 的 Cookie 不会自动进入访客浏览器，须验证真实传递路径。
2. `/ask` 与 `/quota` 的请求、响应类型和机器可读错误；明确重置时区、`reset_at`、可重试条件及必要的等待时间。现有参数校验状态码与网关非 JSON 错误也须有处理约定。
3. 个人额度与全站预算的原子检查/预留/结算规则，包括缓存、繁忙拒绝、上游失败、超时后仍在执行的调用、重复请求和 SDK 重试，避免重复扣减或漏记成本。
4. 默认 Key 与 BYOK 的费用归属；BYOK 仍可能消耗站点 Embedding 和计算资源，不等于无限免费。明确其他可触发付费调用的入口如何受控。
5. 匿名凭证只能识别会话，不能保证一个自然人只有一个身份；需说明新身份申请限流、代理可信边界和全站上限。无效凭证不应由前端静默反复重建来规避限制。
6. 单进程/多进程部署约束、持久化路径、并发一致性、损坏或写入失败策略；输入、输出与模型重试上限应支持可执行的预算边界。
