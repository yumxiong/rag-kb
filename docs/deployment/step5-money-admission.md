# Step 5 每日人民币 50 元统一准入

2026-10-16，本地源代码实现；用户接受保守首版。尚未调用真实供应商、构建新镜像
或部署。本说明与[部署参数记录](step5-deployment-decisions.md)配套。

## 金额与计费范围

硬上限为每个 UTC 日 50,000,000 微元，即 50 元人民币。用整数计数，无浮点累计。
既有个人/全站次数限额继续独立生效，不能用提高次数限额绕过金额准入。

| 调用 | 发送前保守预留 |
| --- | --- |
| deepseek-flash 聊天 | 1,100,000 输入 token × 2 元/百万 + 输出上限 × 8 元/百万；800 输出时 2.2064 元 |
| qwen3.7-text-embedding | 每条按 128,000 token × 0.5 元/百万，即 0.064 元 |
| text-embedding-v3 回退 | 每条按 8,192 token × 0.5 元/百万，即 0.004096 元 |

聊天输入按整个模型窗口预留，1.1M 覆盖 1M 的十进制/二进制解释，不以未经验证的
字符/token 换算缩小预留。聊天仍限制序列化消息 32 KiB、最多 800 输出、关闭 thinking、
不流式、单个 completion、无自动重试。向量仍 1024 维、批量配置 10、15 秒超时。
当前 LangChain 兼容文本模式实际逐条发 HTTP，每条单独预留；多条 HTTP 批次按条数预留。
所有既有切片参数不变。

项目聊天、查询向量化、文档导入/重建、验收共用金额余额。真正的用户自带密钥聊天
不占项目金额；项目密钥的 embedding 仍计入。提交与配置项目聊天密钥相同的覆盖
密钥仍按项目计费。纯缓存命中没有 HTTP 调用，不新增金额，但 ask 仍按原契约计次。

只允许受审查的精确地址与模型：DeepSeek `/chat/completions` 和 DashScope
`/compatible-mode/v1/embeddings`；未知模型、地址、维度或请求选项直接拒绝。
此首版也会阻止其他默认供应商配置，不能把旧的通用配置能力视为已获得定价审核。

## 持久化、故障与跨日

发送 HTTP 前，在现有 `AnonymousSessionStore` 进程锁、线程锁和原子持久化机制内
写入 reservation。同步/异步 HTTP transport 都受保护，SDK 拆批或任何实际重试
都需要独立预留；禁止环境代理绕过 transport。后台线程使用应用注册的同一账本。
余额不足返回 `global_budget_exceeded`；存储不可用返回 `quota_storage_unavailable`。

成功响应必须完整读完才结束未决状态，已预留金额当天不退还。网络异常、超时、
响应体中断及非 2xx 都保留未决预留；它们在后续每一天继续占用可用额度，重启不清除。
跨日成功在发送日和完成日都保留费用；在途期间已占用后续日余额，不能靠午夜并发
绕过限额。跨日不是未决金额的自动退款点；公开 Retry-After 只是下一个 UTC 日界，
不保证该时刻恢复可用。没有个人重置、缓存清理或普通管理接口能够释放金额。

未决记录累积可能最终停止全部项目调用。这是选择保守上限的代价；不要手改账本或
重新 bootstrap 清零。未来如需对账释放，必须另行设计可审计、能够证明计费完成的流程。
时钟倒退、价格失效、账本写入失败都拒绝新付费请求。

金额放在既有 `quota-state-v1.json` 的独立 `money` 区块，复用同一个 reference。
首次显式 bootstrap 创建空金额状态；已有账本缺少该区块时拒绝注册/付费调用，
不会自动补零。当前项目尚未部署，不需要自动迁移生产账本。若有既有消费的账本，
须停服、核账并另行审查迁移，禁止删除旧状态来获得新的 50 元。
管理员预算快照新增 `money` 字段，单位是微元；`actual_billed=null`，不能当真实消费。

## 离线工具与适用边界

独立导入、重建或验收工具必须在后端停止后打开同一部署路径的账本，使用
`offline_provider_access(reason=..., ledger=store)`，并调用受保护的项目模型组件。
只声明 offline 权限而没有账本不会获得付费许可。后端运行中不能再打开第二个 owner；
后台作业应在该后端进程内运行。不能为每次验收创建新金额账本，也不能用裸 SDK、
curl 或供应商控制台调用项目密钥作为“预算内验收”。本轮未执行任何这种调用。

项目密钥须专用；应用无法拦截外部持有密钥的程序、其他凭据对应的消费，也不能
检测用户提供的另一把密钥是否恰好属于同一计费账户。BYOK 须确为用户自行支付。
账本约束的是受审查价格下、经本应用发出的费用上界，供应商调价或延迟记账可能与
应用 UTC 日界不同；这不是对供应商账户最终日账单无条件不超过 50 元的保证。
真实供应商验收须核对有效价格、模型限制、计费单位及账号适用条件。
